# FindTree privileged-to-visual curriculum

This experiment is isolated from `MineRLTreechop-v0`. It is a small diagnostic
curriculum, not the final forest navigation system and not a claim that a full
RL policy has been trained.

## Task

- Flat grass world generated by Malmo.
- One three-block `log` trunk with a leaf canopy, placed 5--8 blocks away.
- Agent starts at a fixed position. Curriculum stage 1 uses target-relative yaw
  noise of +/-30 degrees; stage 2 widens it to +/-90 degrees, so the trunk can
  begin outside the camera view.
- Navigation actions: noop, forward, forward+jump, turn left/right, look up/down.
- Success: horizontal distance to the locked trunk is at most 1.8 blocks.
- Default project limit: 100--250 steps, independent of MineRL's server limit.

The flat task deliberately removes forest occlusion, long-range exploration and
obstacle avoidance. Those are later curriculum stages.

## Observations and information boundary

Malmo produces three raw observations:

1. `pov`: uint8 RGB, shape `(64, 64, 3)`.
2. `privileged_pose`: x/y/z, yaw and pitch from `ObservationFromFullStats`.
3. `log_grid`: binary `(6, 21, 21)` mask created from
   `ObservationFromGrid`; Malmo's flattened x-fastest ordering is reshaped as
   `(y, z, x)`.

The wrapper locks the nearest observed trunk in world coordinates on reset and
computes the training-only vector:

```text
[target_available,
 horizontal_distance,
 sin(relative_yaw),
 cos(relative_yaw),
 relative_height]
```

The visual policy receives only `pov`. The vector is used by the oracle teacher,
reward calculation and metrics. It is never passed to `LinearVisualPolicy`.
This is the information boundary that implements "privileged training, visual
deployment": privileged state supplies labels during collection, but the
deployed action call cannot read it.

## Reward

```text
reward_t = distance_(t-1) - distance_t - 0.01
reward_t += 5.0 on success
```

The target is locked for the episode, avoiding nearest-tree switching reward
artifacts. Raw MineRL collection reward is recorded in `info` but is not used.

## First learning check

The model intentionally uses only NumPy/OpenCV:

- spatial RGB plus Sobel gradient features;
- linear softmax action classifier;
- class-balanced teacher-action loss;
- horizontal reflection augmentation with left/right label swapping;
- validation split by complete episode, not adjacent-frame random splitting;
- a validation-selected forward bias to correct deployment action priors.
- an optional causal frame stack, padded with the episode's first frame and
  never allowed to cross an episode boundary.

For the +/-90 degree stage, the teacher always scans clockwise while the target
is outside an assumed +/-40 degree visual field. This avoids teaching an
unobservable shortest-turn label. Once the target is visible, the teacher turns
toward it and moves forward. The student receives four consecutive POV frames,
which make scan direction and recent target motion observable.

This is a cheap test of whether privileged labels contain learnable visual
signal. It is not the intended final CNN/GRU or asymmetric actor-critic.

## Reproduce

```powershell
python -m scripts.collect_find_tree --episodes 16 --max-steps 100 --seed 42
python -m scripts.train_find_tree_vision --epochs 250 --learning-rate 0.01 --feature-size 6
python -m scripts.evaluate_find_tree --episodes 5 --max-steps 100 --seed 1000
```

Stage 2 (wider initial yaw and four-frame visual memory):

```powershell
python -m scripts.collect_find_tree --episodes 20 --max-steps 130 --seed 3000 --yaw-noise 90 --student-observable-teacher --output logs/find_tree/oracle_dataset_yaw90.npz
python -m scripts.train_find_tree_vision --dataset logs/find_tree/oracle_dataset_yaw90.npz --model checkpoints/find_tree_visual_yaw90_stack4.npz --history logs/find_tree/training_history_yaw90_stack4.csv --epochs 300 --learning-rate 0.01 --feature-size 6 --frame-stack 4 --patience 40
python -m scripts.evaluate_find_tree --episodes 10 --max-steps 130 --seed 4000 --yaw-noise 90 --model checkpoints/find_tree_visual_yaw90_stack4.npz --output logs/find_tree/evaluation_yaw90_stack4.csv
```

Full-yaw zero-shot gate (no new collection or training):

```powershell
python -m scripts.evaluate_find_tree --episodes 20 --max-steps 160 --seed 5000 --yaw-noise 180 --model checkpoints/find_tree_visual_yaw90_stack4.npz --output logs/find_tree/evaluation_yaw180_zeroshot_20.csv --clockwise-search --modes oracle visual
```

Each Minecraft command has a 4--6 minute cold start on the verified machine.
The train command is offline and completes in seconds.

## Results from 2026-08-15

Teacher collection, seeds 42--57:

- 16/16 oracle success;
- 422 transitions;
- 18--35 steps per episode;
- hot resets approximately 16 seconds.

Episode-held-out supervised validation:

- validation loss: 1.099 -> 0.729 (33.7% reduction);
- tail loss standard deviation: 0.0039;
- calibrated balanced action accuracy: 99.4%;
- forward calibration bias selected only on held-out training episodes: 0.35.

Paired real Minecraft evaluation, unseen seeds 1000--1004:

| Policy | Success | Mean steps | Mean final distance |
|---|---:|---:|---:|
| Uniform random | 2/5 | 86.2 | 2.832 |
| Privileged oracle | 5/5 | 28.4 | 1.697 |
| Visual before calibration | 1/5 | 87.8 | 2.595 |
| Visual after calibration | 4/5 | 47.6 | 1.717 |

This is a preliminary improving trend, not statistical proof of stability. Five
evaluation worlds produce wide confidence intervals. The calibrated policy also
uses the same simple arena distribution as training. It has not been tested in a
forest, with a target initially behind the agent, or with obstacles.

### Stage 1 gate and stage 2 result

The stage 1 policy was then evaluated on 20 new paired seeds (2000--2019):

| Policy | Success | Wilson 95% CI | Mean steps | Mean final distance |
|---|---:|---:|---:|---:|
| Uniform random | 5/20 | 11.2%--46.9% | 87.20 | 3.830 |
| Privileged oracle | 20/20 | 83.9%--100% | 24.90 | 1.672 |
| POV-only visual | 20/20 | 83.9%--100% | 26.85 | 1.695 |

This passes the predefined stage 1 gate, including a Wilson lower bound above
80%. Stage 2 teacher collection on seeds 3000--3019 was also 20/20 successful
and produced 710 transitions (mean 35.5 steps, maximum 59 of 130).

Stage 2 episode-held-out validation:

- validation loss: 1.099 -> 0.327 (70.2% reduction);
- tail loss standard deviation: 0.00079;
- best validation accuracy: 86.1%;
- calibrated validation accuracy: 89.4%;
- four-frame policy input; no privileged state in the policy call.

Paired real Minecraft evaluation on unseen seeds 4000--4009:

| Policy | Success | Wilson 95% CI | Mean steps | Mean final distance | Mean reward |
|---|---:|---:|---:|---:|---:|
| Uniform random | 1/10 | 1.8%--40.4% | 123.5 | 6.406 | -0.277 |
| Privileged oracle | 10/10 | 72.2%--100% | 27.9 | 1.671 | 9.914 |
| Four-frame POV-only visual | 10/10 | 72.2%--100% | 30.7 | 1.666 | 9.891 |

The visual policy matched or beat oracle step count on 6/10 paired seeds. Its
median overhead was 0 steps and mean overhead was 2.8 steps. This is a stable
improving trend within the simple flat arena. It is not yet proof of general
forest navigation: the stage 2 sample has a wide confidence interval, only one
tree exists, and there are no distractors, occlusions or obstacles.

The evaluation was extended through seed 4019. The raw classifier reached
18/20 success (90%, Wilson 95% CI 69.9%--97.2%). Failure traces showed an exact
left/right limit cycle: on seed 4013 it issued 70 left, 60 right and zero
forward actions, leaving distance unchanged for all 130 steps. This was not a
navigation-reward failure; it was an unobservable search-direction decision on
empty sky/grass frames.

`--clockwise-search` implements the same information-safe convention used by
the teacher: both visual turn predictions map to clockwise search, while the
POV model alone decides when to move forward. A complete rerun on seeds
4000--4019 produced:

| Policy | Success | Wilson 95% CI | Mean steps | Median steps | Mean final distance |
|---|---:|---:|---:|---:|---:|
| Uniform random | 3/20 | 5.2%--36.0% | 118.75 | 130.0 | 5.889 |
| Privileged oracle | 20/20 | 83.9%--100% | 27.20 | 27.0 | 1.700 |
| Raw four-frame visual | 18/20 | 69.9%--97.2% | 39.25 | 30.0 | 2.071 |
| Visual + consistent clockwise search | 20/20 | 83.9%--100% | 43.95 | 40.5 | 1.687 |

The consistent-search policy passes the 20-seed gate but is less efficient:
mean/median overhead over oracle is 16.75/11 steps. This is an explicit
reliability-efficiency tradeoff, not a claim that the visual policy has matched
privileged shortest-path navigation.

### Stage 3: full-yaw zero-shot evaluation

Before collecting more demonstrations, the unchanged +/-90-degree model was
evaluated zero-shot with initial yaw noise widened to +/-180 degrees. The only
deployment convention retained was consistent clockwise search. On unseen
seeds 5000--5019:

| Policy | Success | Wilson 95% CI | Mean steps | Mean final distance | Mean reward |
|---|---:|---:|---:|---:|---:|
| Privileged oracle | 20/20 | 83.9%--100% | 34.05 | 1.661 | 9.997 |
| Zero-shot visual + clockwise search | 20/20 | 83.9%--100% | 47.60 | 1.661 | 9.862 |

Visual mean/median step overhead was 13.55/7, the slowest episode took 77 of
160 allowed steps, and visual matched or beat oracle steps on 6/20 seeds. No
new labels or training were required. Full-yaw search therefore passes in this
arena; the next curriculum variable should be scene ambiguity (distance,
distractor trees or occlusion), not more yaw-only data.

### Stage 4: variable target distance

The target distance range was widened from the original 5--8 blocks to 3--10
blocks while retaining full yaw. The existing model's zero-shot result on
seeds 6000--6019 was 17/20 (85%, Wilson 95% CI 64.0%--94.8%). Distance bins
showed the failure was concentrated at small visual scale:

| Actual initial distance | Success | Mean steps |
|---|---:|---:|
| `<5` | 5/5 | 30.8 |
| `5--9` | 7/8 | 73.1 |
| `>=9` | 5/7 | 137.3 |

Two far failures issued 219--220 clockwise turns and at most one forward
action. A new dataset was therefore collected on seeds 7000--7031: 32/32
teacher success and 1,229 transitions. The four-frame linear probe used 8x8
spatial features to retain more detail for distant trees. Held-out validation
loss fell from 1.099 to 0.231 (79.0%), with 91.3% calibrated balanced accuracy.

Retrained evaluation on unseen seeds 8000--8019:

| Policy | Success | Wilson 95% CI | Mean steps | Median steps |
|---|---:|---:|---:|---:|
| Privileged oracle | 20/20 | 83.9%--100% | 38.5 | 38.0 |
| Distance-trained visual | 20/20 | 83.9%--100% | 45.5 | 46.0 |

Visual mean/median step overhead was 7/2 steps. The distance stage passes.

### Stage 5: two identical distractor trees

Each episode contains one target and two identical distractor trees. The target
is always the nearest tree at reset; distractors are at least two nominal blocks
farther away and separated around the agent. The oracle locks the initial
nearest tree. Thus target identity is visually inferable only by comparing
apparent scale across candidates; success is not awarded for reaching any tree.

On unseen seeds 9000--9019:

| Policy | Success | Wilson 95% CI | Mean steps | Median steps |
|---|---:|---:|---:|---:|
| Privileged oracle | 20/20 | 83.9%--100% | 37.35 | 37.0 |
| Distance-trained visual | 16/20 | 58.4%--91.9% | 107.5 | 63.0 |

Successful visual episodes averaged 59.4 steps. All four failures exhausted
300 steps and finished 9.86--13.85 blocks from the locked target. Their action
traces contained 33--44 forward actions followed by 256--267 clockwise turns,
consistent with committing to a distractor and lacking a recovery/replanning
state. The point estimate touches 80%, but the wide interval and catastrophic
failure mode mean this stage does not pass the stability gate.

## Gate before the next curriculum stage

Run at least 20 unseen paired seeds and require:

- visual success rate >= 80%;
- visual mean final distance lower than random;
- no use of oracle in the policy call path;
- performance reported with confidence intervals;
- failure frames inspected for oscillation or target loss.

Stages 1--4 passed. Stage 5 did not pass, so natural `MineRLTreechop-v0` forest
deployment was deliberately not run. The next implementation should introduce
episode-scale candidate memory and recovery: scan a full circle, retain a score
for each candidate, select the closest-looking tree, and abandon/replan when
forward progress stalls. A GRU or an explicit candidate map is now justified;
blindly adding more single-frame imitation data is not.

### Stage 6: explicit candidate map baseline (2026-08-17)

The new baseline implements an inspectable state machine:

`SCAN -> BUILD_CANDIDATE_MAP -> SELECT_TARGET -> ALIGN -> APPROACH -> LOCAL_REACQUIRE -> RECOVER -> REPLAN`.

It uses only POV, commanded camera deltas, and internal memory for deployment
actions. Oracle distance and the generated log grid remain evaluation-only.
The scan issues 36 clockwise 10-degree camera commands. Tree detections combine
a brown trunk component with its upper-image leaf canopy. Only detections in
the central +/-14 degrees are inserted into memory because Minecraft's wide
projection stretches edge objects. Temporal detections merge within 45 degrees
and a 1.6 log-scale difference; a post-scan 55-degree pass joins tracks split
by one missed frame or the 0/360 boundary. Candidate scale is always taken from
the most centred view. A cooldown candidate may merge across arbitrary scale
change at a matching bearing, since approaching the same object legitimately
changes its apparent size by an order of magnitude.

The deployment score is:

`confidence + 2*log(apparent_size + 1e-3) - 0.15*abs(turn)/180 - attempts - 0.002*age`.

The 20-step progress window requires at least 12 forward actions and flags a
stall when apparent size grows by less than 8%, alignment improves by less than
2 degrees, and frame change is low, visibility is poor, or scale is decreasing.
Six consecutive misses trigger local reacquisition. Recovery scans +/-30
degrees, backs up five steps, turns right three steps, retries once, then puts
the candidate in a 45-step cooldown. Replan preserves cooldown identities and
rescans from the translated location.

Real Minecraft results (new seeds, two distractors, full yaw, distance 3--10,
300-step cap):

| Run | Success | Wilson 95% CI | Initial selection | Mean / median steps | Recovery / replan |
|---|---:|---:|---:|---:|---:|
| Smoke 10000--10002 | 3/3 | 43.9%--100% | 3/3 | 73.7 / 80.0 | 0 / 0 |
| Paired oracle 11000--11019 | 20/20 | 83.9%--100% | n/a | 36.75 / 39.5 | n/a |
| Candidate 11000--11019 | 20/20 | 83.9%--100% | 20/20 | 75.2 / 76.5 | 1 / 0 |
| Candidate 12000--12029 | 30/30 | 88.7%--100% | 30/30 | 72.5 / 70.0 | 2 / 0 |

The ordinary-distribution result improves on stage 5's 16/20 success and 107.5
mean steps, with no 300-step failures. However, all 50 ordinary candidate
episodes selected the nearest tree initially, so they do not validate recovery
from a wrong initial choice. A clearly labelled diagnostic forced score rank 1
on seeds 13000--13002. It produced 2/3 success in v1, 1/3 after an intermediate
rescan change, and 2/3 after cooldown identity matching. The persistently failing
seed 13000 still ended at 300 steps. Its trace shows the agent walked to a
distractor until the target was about 21 blocks away; a POV rescan then saw only
the nearby failed tree. Commanded-yaw memory alone cannot recover the world
position of now-distant candidates after translation.

Therefore the strict natural-Treechop gate is **not passed**. Natural
`MineRLTreechop-v0` was not launched. The next minimal fix is 2-D internal
dead-reckoning for candidate positions (using commanded turns, forward actions,
and a calibrated visual-range estimate), not a GRU, DQN, PPO, or seed-specific
exception.

Known non-fatal Windows shutdown output remains: `Failed to delete the temporary
minecraft directory` and, on some runs, `process already exited`. No Java process
remained after the runs. MineRL must be launched with the isolated environment's
JDK 8; inheriting global JDK 21 fails because JAXB is absent.
